## О проекте

Программа обрабатывает исходную выгрузку медицинских услуг, фильтрует записи по заданному периоду и автоматически формирует отдельный Excel-файл для каждого подразделения женской консультации.

Проект появился из реальной административной задачи: исходная таблица содержит большое количество несортированных строк, а итоговые отчёты необходимо регулярно группировать по врачам и услугам. Ручная подготовка таких файлов занимает много времени и создаёт риск ошибок в количестве услуг и итоговых суммах.

Программа сохраняет исходный файл без изменений и создаёт новые отчёты в отдельной папке.

## Основные возможности

- выбор исходного Excel-файла через стандартное диалоговое окно;
- чтение старого формата `.xls` через `xlrd`;
- чтение `.xlsx` и `.xlsm` через `openpyxl`;
- фильтрация данных по начальному и конечному дням включительно;
- автоматическое определение листа и необходимых столбцов;
- поддержка нескольких вариантов названий заголовков;
- выделение только подразделений женских консультаций;
- создание отдельного файла для каждого уникального подразделения;
- сортировка услуг по врачу, коду и наименованию;
- объединение повторяющихся услуг одного врача;
- сохранение ведущих нулей в кодах услуг;
- автоматический расчёт суммы по формуле `Тариф × Кол-во`;
- разные цветовые темы для разных подразделений;
- фильтры, закреплённая шапка и настройка печати на листе A4;
- безопасные имена выходных файлов и защита текстовых ячеек от формул;
- работа как в интерактивном режиме, так и через командную строку.

## Бизнес-логика

Строки объединяются по следующему составному ключу:

```text
Подразделение + Врач + Код услуги + Наименование услуги + Тариф
```

Количество одинаковых услуг суммируется. Если у одинакового кода услуги встречаются разные тарифы, такие записи остаются отдельными строками. Это позволяет сохранить корректность финансового результата.

Итоговый файл содержит столбцы:

| Столбец                        | Содержание                                                    |
| ------------------------------------- | ----------------------------------------------------------------------- |
| Врач                              | ФИО из исходной колонки`Врач`                 |
| Код услуги                   | Код услуги с сохранением ведущих нулей |
| Наименование услуги | Полное название услуги                              |
| Тариф, руб.                   | Тариф из исходной выгрузки                       |
| Кол-во                           | Суммарное количество одинаковых услуг |
| Сумма, руб.                   | Формула`Тариф × Кол-во`                             |

## Требования к исходной таблице

Программа ищет следующие обязательные поля:

| Обязательное поле     | Примеры поддерживаемых заголовков                                                |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Дата                              | `Дата`, `Дата услуги`, `Дата оказания услуги`                             |
| Код услуги                   | `Код услуги`, `Код медуслуги`                                                          |
| Наименование услуги | `Наименование услуги`, `Название услуги`, `Услуга`                  |
| Количество                  | `Кол-во`, `Количество`, `Количество услуг`                                  |
| Тариф                            | `Тариф`, `Цена`, `Цена / тариф, руб.`                                                |
| Врач                              | `Врач`, `ФИО врача`                                                                             |
| Подразделение            | `Подразделение`, `Наименование подразделения`, `Отделение` |

Порядок столбцов не имеет значения. Дополнительные столбцы допускаются и не изменяются.

## Установка

Требуется Python 3.10 или новее.

```bash
python -m pip install openpyxl xlrd
```

Для изолированной установки рекомендуется виртуальное окружение:

```bash
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install openpyxl xlrd
```

## Интерактивный запуск

```bash
python zhk_report.py
```

После запуска программа:

1. откроет окно выбора исходного файла;
2. запросит начальную дату;
3. запросит конечную дату;
4. обработает записи;
5. создаст папку с готовыми отчётами рядом с исходным файлом;
6. выведет статистику обработки в консоль.

Формат ввода даты:

```text
31.08.2026
```

## Запуск через командную строку

```bash
python zhk_excel_report.py \
  --input "услуги.xls" \
  --date-from 31.08.2026 \
  --date-to 31.08.2026 \
  --no-pause
```

Дополнительные параметры:

| Параметр      | Назначение                                                           |
| --------------------- | ------------------------------------------------------------------------------ |
| `--input`           | Путь к исходному файлу                                      |
| `--date-from`       | Начальная дата периода                                     |
| `--date-to`         | Конечная дата периода                                       |
| `--output-dir`      | Папка для сохранения результатов                  |
| `--sheet`           | Явное имя исходного листа                                |
| `--all-departments` | Формировать отчёты по всем подразделениям |
| `--no-pause`        | Не ожидать нажатия Enter после завершения       |

## Результат работы

Для каждого подразделения создаётся отдельный файл:

```text
Женская консультация №5__31.08.2026-31.08.2026.xlsx
```

Все файлы помещаются в новую папку:

```text
Отчёты_ЖК_31.08.2026-31.08.2026/
```

Если такая папка уже существует, программа создаёт новый каталог с временным суффиксом и не перезаписывает предыдущие результаты.

## Архитектура

Код разделён на классы с отдельными зонами ответственности:

| Компонент         | Ответственность                                                           |
| -------------------------- | ---------------------------------------------------------------------------------------- |
| `AppConfig`              | Централизованные настройки приложения                 |
| `HeaderResolver`         | Поиск и проверка заголовков исходной таблицы      |
| `XlsWorkbookAdapter`     | Адаптация старого формата`.xls`                                 |
| `SourceReader`           | Потоковое чтение, фильтрация и агрегация данных |
| `DepartmentData`         | Хранение агрегированных услуг подразделения      |
| `ReportWorkbookWriter`   | Создание и оформление итоговых книг                       |
| `OutputDirectoryFactory` | Безопасное создание выходного каталога                |
| `ReportApplication`      | Управление полным сценарием выполнения                |

Такое разделение позволяет независимо изменять правила фильтрации, алгоритм агрегации, оформление отчётов или способ получения входных данных.

## Производительность

Для `.xlsx` используется режим последовательного чтения `read_only=True`. Программа не загружает исходную книгу целиком в редактируемом виде.

Временная сложность обработки — `O(n)`, где `n` — количество строк исходной таблицы. Память используется преимущественно для уникальных агрегированных комбинаций, а не для хранения всех исходных записей.

Это позволяет обрабатывать крупные медицинские выгрузки значительно быстрее ручной сортировки и копирования данных.

## Надёжность

В программе предусмотрены:

- проверка обязательных колонок;
- проверка формата и диапазона дат;
- обработка чисел с точкой, запятой и пробелами;
- сохранение кодов услуг как идентификаторов;
- отдельный учёт строк с отсутствующим количеством;
- пропуск повреждённых строк с выводом понятных предупреждений;
- округление денежных значений до копеек;
- атомарное сохранение через временный файл;
- запрет на изменение исходной книги;
- защита от случайной вставки Excel-формул из текстовых полей.

## Конфиденциальность медицинских данных

Репозиторий не должен содержать реальные сведения о пациентах, номера полисов, даты рождения, диагнозы или другие персональные данные.

Для демонстрации проекта используйте только:

- полностью синтетические данные;
- обезличенные примеры;
- скриншоты без персональной информации;
- тестовые ФИО и идентификаторы, не относящиеся к реальным людям.

Программа переносит в итоговый отчёт только сведения о враче и оказанных услугах. Пациентские данные из исходной выгрузки в отчёты не записываются.

## Ограничения

- защищённые паролем книги не поддерживаются;
- `.xls` используется только как входной формат;
- результаты сохраняются в `.xlsx`;
- `xlrd` читает сохранённые результаты формул из `.xls`, но не вычисляет формулы самостоятельно;
- при нестандартных названиях столбцов их варианты необходимо добавить в `HeaderResolver.ALIASES`.
